# Исследование: перенаправление App Groups в сторонних проектах

Контекст: профиль пользователя (Team `9U945T…`, explicit App ID `app.yam53.taro5888`)
разрешает пять фиксированных групп `group.c2fefdd0db2e255e.1`–`.5`, а Swiftgram
запрашивает вычисляемую `group.<bundle-id>`. Задача — понять, как сторонние
проекты решают это несоответствие, чтобы перенять принцип (без внедрения
runtime-хуков на первом этапе).

Источники: отчёт «Swiftgram Signing Compatibility» от 13.10.2026
(стр. 4–9, 14–15), репозитории проектов.

---

## 1. Цепочка TGExtra → ipapatch → zxPluginsInject

### TGExtra (https://github.com/axs66/TGExtra)

Динамическая библиотека с дополнительными функциями для Telegram-подобных
приложений, внедряемая в IPA.

- В injection filter явно входит `app.swiftgram.ios` (commit `087f265…` в отчёте).
- Рабочий workflow вызывает **ipapatch** для внедрения библиотеки в бинарники.
- Исторически в workflow оставался скачиваемый SideloadFix, но в актуальную
  команду injection он **не передаётся** — смешивать старый fallback и нынешний
  механизм нельзя.

### ipapatch

Инструмент подготовки IPA (используется TGExtra как движок внедрения).

- Находит executable главного `.app` и всех `.appex`, **исключая Watch-таргеты**
  (commit `2ccafe4…`).
- Добавляет загрузку библиотеки (load command `LC_LOAD_DYLIB`) в каждый
  исполняемый файл. Ключевой момент: исправление попадает и в **процессы
  расширений** (виджет), а не только в главный бинарник.

### zxPluginsInject (commit `d849cd5…` в отчёте)

Содержит саму логику редиректа App Groups:

1. Через **приватный API** `LSBundleProxy` получает список App Groups, реально
   разрешённых для приложения, и их настоящие container URLs.
2. Выбирает **первую** группу и кэширует результат (ранний кэшированный выбор).
3. Запрос старого идентификатора группы перенаправляется в
   `<real-shared-group>/<original-group-id>` — то есть путь находится
   **внутри настоящего системного общего контейнера**, в подкаталоге,
   названном по исходному идентификатору.
4. Приватный инициализатор `NSUserDefaults` отдельно перенаправляет suite-имена
   с префиксом `group.`.

Итог схемы: если main и widget выбирают одну и ту же реальную группу и один
логический подкаталог — это **настоящее межпроцессное sharing**. При
отсутствии реальной группы код падает обратно в приватный `Documents`
(обмен между процессами при этом теряется).

## 2. Оценка схемы

### Что в ней хорошо

- Редирект в реальный системный контейнер — не фиктивная папка: настоящий
  App Group API, настоящий sandbox.
- Подкаталог `<original-group-id>` внутри контейнера — примитивный namespace:
  несколько логических «групп» могут жить в одной физической.
- Внедрение на уровне каждого executable — расширения получают тот же shim.

### Что в ней рискованно (почему НЕ внедряем сразу)

- **Порядок пяти групп не является назначением**: «первая» не обязана иметь
  суффикс `.1`; разные порядок/подмножества разделяют данные.
- **Приватный API** (`LSBundleProxy`, приватный `NSUserDefaults.init`) —
  нестабилен между версиями iOS, риск отклонения/падения.
- **Ранний кэшированный fallback** — если группа временно недоступна,
  кэш может законсервировать неверное решение.
- Общий пакет меняет также **keychain и CloudKit** (включая возврат `nil` при
  создании `CKContainer`) — это может отключить посторонние функции.
- Встроенный binary ipapatch не был доказанно сопоставлен с исследованным
  source-коммитом.

## 3. Что переносим в AppGroupProbe (и позже в Swiftgram)

Принцип, а не библиотеку:

| Принцип из zxPluginsInject | Реализация в AppGroupProbe |
|---|---|
| Одна реальная группа, выбранная явно | `PROBE_APP_GROUP_ID: group.c2fefdd0db2e255e.1` в `project.yml` (settings.base, общие для таргетов) |
| Одинаковая группа у всех процессов | один и тот же `AppGroupIdentifier` в Info.plist app и widget |
| Namespace-подкаталог вместо «первой попавшейся» группы | `AppGroupProbe/probe-token.json` внутри контейнера |
| Настоящий системный контейнер | только `containerURL(forSecurityApplicationGroupIdentifier:)` |
| Диагностика при отсутствии права | явные `ProbeError.containerUnavailable` / `fileNotFound` в UI и виджете |

Без runtime-хуков и приватных API. Если тест покажет, что GBox не сохраняет
App Groups при переподписи — следующим шагом будет минимальный compatibility
shim (перенаправление только в рамках публичного API и только для конкретного
идентификатора), но это отдельный эксперимент после провала первого.
